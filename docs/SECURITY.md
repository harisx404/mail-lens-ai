# Security

## Design principles

Mail-Lens AI performs static analysis only. It never:
- Visits or resolves any URLs found in analyzed emails
- Executes or opens any files referenced in emails
- Sends email content to external APIs or services
- Stores analyzed emails to disk

## Input handling

**Input size:** Email body is capped at 50,000 characters (`MAX_EMAIL_LENGTH` in `config.py`). Streamlit's `max_chars` parameter enforces this in the UI.

**Empty / whitespace inputs:** The inference engine strips combined text before processing. A fully blank input returns `UNKNOWN` status rather than a false prediction.

**HTML content:** If a user pastes raw HTML email source, the preprocessor strips all tags using BeautifulSoup before NLP processing. HTML content does not affect the classifier's input vector.

**XSS prevention:** All user-controlled strings (sender, subject, body) that appear in rendered HTML output are escaped with `html.escape()` before injection into `unsafe_allow_html=True` blocks. Token chip labels and recommendation text are also escaped.

Tests for XSS injection are in `tests/test_qa_regression.py`:
- `test_xss_injection_in_sender_and_reasons`
- `test_xss_escaping_in_highlighter`

**Injection strings:** SQL injection and shell command strings are processed as plain text tokens. They have no effect on the inference pipeline, which operates entirely within Python's data structures.

## Model loading security

The application loads serialized `joblib` artifacts from the local filesystem. The model files in `models/saved/` are generated by `scripts/train.py` from known training data. The loading path is constructed from an absolute base directory and does not accept user-supplied paths.

`joblib.load()` uses Python's `pickle` protocol internally. Loading untrusted model files can execute arbitrary code. **Only load model files that you generated yourself or trust the source of.**

## Privacy

**No data persistence:** Email content submitted through the UI exists only in Streamlit session state (in-process memory). It is not written to disk, logged, or sent to any external service.

**No analytics or telemetry:** The application does not include any tracking, error reporting, or analytics collection.

**Secrets:** The application requires no API keys or credentials for standard operation. See `.env.example` for configurable settings. Never commit a `.env` file.

## Server configuration

When running with Streamlit:
- `enableCORS = true`: Cross-origin requests are allowed (Streamlit default behavior)
- `enableXsrfProtection = true`: XSRF tokens are validated on form submissions

For production exposure (making the app accessible beyond localhost), consider placing Streamlit behind a reverse proxy (nginx, Caddy) with HTTPS and appropriate access controls.

## Dependency security

Dependencies are pinned to minimum versions in `requirements.txt`. Run the following to check for known vulnerabilities:

```bash
pip install pip-audit
pip-audit
```

## Limitations

- This is a prototype application, not hardened production security software
- There is no authentication or rate limiting — do not expose this to untrusted networks without additional controls
- Model artifacts are not cryptographically signed; an attacker with filesystem access could replace them
- The application has not undergone a formal penetration test
