05 / 10 Feature Engineering

NLP Pipeline & Feature Fusion

Combining statistical NLP features with domain-specific cybersecurity indicators into a 10,020-dimensional feature space.

NLP Preprocessing Pipeline

Raw Email ├─ 1. HTML Stripping (script/style removal) ├─ 2. URL Normalization → "urlplaceholder" ├─ 3. Email Normalization → "emailplaceholder" ├─ 4. Unicode NFKD (anti-homoglyph) ├─ 5. Case Folding (lowercase) ├─ 6. Noise Cleaning (alphanumeric only) └─ 7. WordNet Lemmatization

Design Choice: Stopwords are preserved — function words like "your account" and "verify you" are highly discriminative for phishing detection.

06 / 10 Data Integrity

Data Leakage Prevention & Split Strategy

Rigorous stratified splitting with strict isolation between training, validation, and test data. TF-IDF vocabulary fitted exclusively on training data.

Unified Dataset (17,960 emails) │ ├── Train Set (70% = 12,572) │ • LEGITIMATE: 7,684 │ • PHISHING: 4,764 │ • MALICIOUS: 124 │ ├── Validation Set (10% = 1,796) │ • LEGITIMATE: 1,098 │ • PHISHING: 680 │ • MALICIOUS: 18 │ └── Test Set (20% = 3,592) • LEGITIMATE: 2,196 • PHISHING: 1,361 • MALICIOUS: 35 ⛔ NEVER used during training!

Leakage Prevention Guarantees

  • TF-IDF Vocabulary: Fitted ONLY on training split. Validation and test data are transformed-only (no fitting).
  • Security Features: Stateless keyword matching — no fitted parameters to leak.
  • Deduplication: Performed BEFORE splitting to prevent identical emails across splits.
  • Stratified Splits: Class proportions preserved across all three partitions (seed = 42).
  • Model Selection: Best model chosen on validation F1. Final evaluation done ONCE on held-out test set.

✓ Zero data leakage. All reported metrics are on genuinely unseen data.

08 / 10 Risk Assessment

Risk Scoring & Explainability Engine

A prediction without an explanation is useless to a Security Operations Center (SOC) analyst. PhishGuard AI provides calibrated risk tiers and human-readable threat narratives.

Risk Tier System

LevelScore RangeAction
LOW0.00 – 0.30Standard delivery, minimal concern
MEDIUM0.30 – 0.60Review recommended, suspicious indicators
HIGH0.60 – 0.85Probable threat, escalate to SOC
CRITICAL0.85 – 1.00Confirmed attack indicators, immediate action

Security Indicator Override

If 3+ threat indicators fire AND the model's non-legitimate probability exceeds 15%, the risk level is automatically elevated to HIGH — even if the classifier predicts LEGITIMATE. This prevents adversarial meta-language from suppressing warnings.

Explainability Output

Every analysis provides:

  • Classification with calibrated probability distribution
  • Numerical risk score (0.0 – 1.0) with color-coded tier
  • Explainable AI (XAI): Mathematical token weights ($w_i \cdot x_i$) showing boundary pull
  • Detected indicators list with specific matched patterns
  • Brand impersonation alerts with similarity percentage
  • Simulation cloaking warnings for adversarial meta-language
  • Actionable recommendations (e.g., "Change passwords", "Run antivirus scan")

Typosquatting Detection

Levenshtein edit distance between email domains and 23 known brand domains. Catches attacks like rnicrosoft.com (edit distance 1 from microsoft.com, 86% similarity).

09 / 10 Limitations & Future

Honest Limitations & Future Roadmap

Academic integrity requires transparent disclosure of system boundaries. PhishGuard AI is a research prototype demonstrating NLP + cybersecurity fusion principles.

Known Limitations

  • MALICIOUS class imbalance: Only 177 malware samples in training data. Detection may be less reliable for novel exploit payloads.
  • English-only: Training corpus is exclusively English. Non-English phishing attacks are not supported.
  • Body-text analysis only: Cannot verify SPF, DKIM, or DMARC cryptographic headers.
  • Static analysis: No URLs are visited, no files are executed — advanced evasions (QR-code phishing, SVG images) require computer vision.
  • Domain shift risk: Trained on specific datasets — real-world enterprise email may have different distributions.
  • Not a replacement for professional email security products (SEGs, sandboxes).

Future Improvements

  • Transformer Fine-Tuning: Fine-tune RoBERTa / DeBERTa-v3 on cyber-specific corpora for improved contextual understanding.
  • Email Header Parsing: Integrate raw .eml RFC 822 parsing (DKIM, SPF alignment, hop analysis).
  • URL Sandbox Integration: Safe sandboxed detonation of suspicious links via VirusTotal API.
  • Multi-Language Support: Extend to Arabic, Urdu, and other languages used in regional phishing campaigns.
  • REST API & SIEM: FastAPI endpoints for integration with Splunk / Microsoft Sentinel.
  • Adversarial Robustness: Evaluate defenses against LLM-generated spear phishing.
